# Operations

## Development workflow

1. Read `AGENTS.md`.
2. Read the relevant product/technical docs.
3. Work in a focused branch/task.
4. Keep changes small.
5. Run repository checks.
6. Review the diff.
7. Document material decisions.

## Pilot operating principle

The first pilot should optimise for learning and trust, not feature count.

Track:
- participating vehicles;
- participating owners;
- association relationship;
- event reliability;
- support incidents;
- data-quality issues;
- consent questions;
- owner usefulness;
- commuter friction.

## Incident categories

At minimum distinguish:
- product bug;
- payment/reconciliation issue;
- data-quality issue;
- privacy/consent issue;
- account/access issue;
- safety concern;
- infrastructure outage.

## Claim governance

Before changing a public target to a verified result:
1. identify the source of truth;
2. verify the metric definition;
3. verify the time period;
4. verify that the number is actually achieved;
5. record the decision.

## Founder/team sustainability

The founder working document explicitly includes avoiding burnout as part of first-year success.

Operational planning should therefore favour:
- small pilots;
- bounded support commitments;
- repeatable processes;
- fewer critical dependencies on one person.
